About this map

Problem statement

This interactive web map supports a housing-affordability and neighbourhood-amenity review for the Borough of Fort Lee, New Jersey. Its purpose is to let the borough's planning office and residents see, in one place, how median household income varies across Fort Lee's ten census tracts alongside the everyday amenities — public schools, grocery stores, parks, and the road and pedestrian networks — that shape quality of life and housing desirability in each neighbourhood.

Intended audience: Fort Lee residents, the borough council and planning staff, and prospective residents — a non-specialist audience, so the design prioritises immediate legibility and self-guided exploration.

Project design justification

Data choices. The layers form one cohesive theme rather than a random collection: a household can only judge a neighbourhood by combining what it costs to live there with what is nearby. The thematic core is median household income, an interval/ratio attribute that is already standardised per household, which is exactly the condition under which a choropleth is the correct technique; mapping it as raw dots or graduated symbols would have falsely implied a countable magnitude. Building on the Lab 4 income map, I added five new OpenStreetMap layers — schools and grocery stores (points), the arterial road network and the pedestrian/cycling network (lines), and parks (polygons) — and joined the ACS income, population and home-value attributes so every tract and amenity returns a meaningful pop-up. All OSM features were clipped to the borough boundary so the map reads as Fort Lee rather than its bbox, and line segments were dissolved by name to keep pop-ups informative and the file lightweight.

Design choices. Visual hierarchy drives the layout: the income choropleth is the figure, rendered in ColorBrewer's YlGnBu five-class sequential ramp classified by Jenks natural breaks, so increasing darkness (lightness/value) reads intuitively as increasing income and the scheme stays colour-vision-deficiency safe. Because the amenity layers are nominal, they are separated by hue and shape instead of value — red school dots, purple grocery dots, green park fills, dark arterial lines — keeping the ordered income variable and the categorical amenities visually distinct. Supporting map elements are all present and easy to find: a persistent title, a structured legend, a scale bar, a layer switcher, pop-ups, two basemaps for context, and this always-available info panel. Balance is managed by anchoring the legend and panel to opposite edges and leaving the dense path network toggled off by default so the reader controls visual load.

Web map vs. a stand-alone hard-copy map. Designing for the browser changed several decisions relative to a printed sheet. Interactivity carries information that a static map must bake into ink: pop-ups replace a crowded data table, the layer switcher lets users declutter (the 1,500-plus path segments would overwhelm a fixed page but are optional here), and pan-and-zoom over a tiled basemap replaces a locator inset and a single fixed scale. In exchange I gave up the guaranteed framing, composition and print resolution of a hard-copy map, and accepted a dependence on connectivity and the reader's screen — so I kept the default extent, symbology and legend deliberately tight so the map still communicates its core message at first load, before any interaction.
